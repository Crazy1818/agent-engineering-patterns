# 可迁移的工程模式（PATTERNS）

> 这不是一套理论，是从一次真实的 Android 自动化项目里**踩出来的**工程模式。
> 每一条背后都至少有一次"系统给自己发了假绿灯"——判据写错、自检假全绿、能量账只记账不踩刹车。

七条模式，每条固定四段：**现场**（带实测数字的翻车现场）→ **抽象**（通用规律）→ **迁移**（搬到哪里）→ **自检清单**（怎么验证你没重复犯错）。

| # | 模式 | 一句话 |
| --- | --- | --- |
| 1 | 判据必须是真实目标 | 代理指标会被系统钻空子，专挑低成本高反馈的无效动作 |
| 2 | 约束收窄优于搜索扩张 | 给动作空间加物理边界，比让系统自由试更省更准 |
| 3 | 读数要变成约束，不是日志 | 观测的唯一价值是限制下一步动作 |
| 4 | 测试必须机器断言 | 人肉 grep 会把"没跑"读成"全绿" |
| 5 | 能量要有否决权 | 记账不叫管理，能切断无效探索才叫管理 |
| 6 | 初始状态推断 | 从半截进入时，别把"看到的"当成"起点" |
| 7 | 无限目标不能当 KPI | 不可证伪的目标只消耗人，不产生方向 |

## 几条最硬的实测数字

- 判据从"画面变了"改成"页码真的推进"后：**15 手 15 页、跨两个章界、零白滑**；
- 假全绿那次：八套实验台根本没跑，日志只有 **206 字节 vs 7208 字节**；
- 能量闸门：JVM 探针 **24/0**，第 13 次连续无收益（patience 100→22）真的进 `COLLAPSE`；
- 给动作加拇指可达边界后，起手点散布从 **15px → 190px**，18/18 全走视觉判据。

## 关于这份文档

它和具体项目（小说、触屏、Android）完全解耦。文末专门列了**哪些是绑定实现、不要搬**——模式会迁移，实现会过时。分清这两者，是这份文档存在的全部理由。

发布前自评：模式 5（能量否决权）机制闭环已做到（约 55%），但"被逼出新策略"仍无实证，如实留在文中，不吹高。

## 为什么这个仓库没有代码

有人会问：讲的全是工程实践，仓库里却只有两个 Markdown，是不是"没有实现的空谈"？

不是。原因有三条，都是刻意的：

1. **这里的定位是方法论沉淀，不是代码开源**。七条模式的目标是能脱离小说、触屏、Android 独立成立；
   把某个 App 的 16000 行 Kotlin 塞进来，反而会掩盖模式本身。
2. **绑定的实现本就不该搬**。拇指可达空间解析解、贝塞尔轨迹、无障碍截图、番茄的页眉正则——
   这些是"实例"，不是"模式"。文末有专门的排除清单。
3. **数字是可复核的**。`15 手 15 页`、`206 字节 vs 7208 字节`、`第 13 次进 COLLAPSE` 都写明了对账方式
   （实验台 / 探针 / 日志），读者可以用自己的系统复现同类验证，而不是只能信我。

所以这里的"0 行代码"是**范围声明**，不是能力声明。唯一例外是文末那个可复现探针 `probe.jar`——
它开源的是**证据**，不是业务实现。想看这些模式如何在一个真实系统里落地、
以及所有翻车的完整病历，需要看的是那个项目的 `SELF_CHECK.md`（1600+ 行逐版复盘）——它没有随本仓库发布。

## 关于引用与"是不是新发明"

不装。这里没有发明新的软件工程原则：真实判据、约束收窄、机器断言、资源熔断、断点续跑——
都是业内有名字的成熟共识（`reward hacking` / `specification gaming` 等在正文里已就地标注）。

**新增的只有一样：把这些原则在一条真实决策链上逐条翻车、逐条量化、逐条修好的完整现场记录。**
这个仓库是病历，不是教科书；可读性来自具体数字，不来自概念创新。若你期待的是理论首创，这里会让你失望——
但如果你正被"系统给自己发假绿灯"这类问题卡住，第 1、4 条的现场可能比一篇新论文更实用。

## 可复现探针（能量否决权）

模式 5 说的"能量要有否决权"不是比喻。它对应一段可运行的判据链：耐心池每次无收益掉 6 点，
连续失败且耐心见底时进入 `COLLAPSE`，第 13 次无收益真的触发，之后 `needsRest()`/`exhausted()` 无缝覆盖。

仓库根目录的 `probe.jar` 把这段判据链和 Kotlin 运行库打在了一起。**不需要 Android，不需要 Kotlin，
不需要 gradle，不需要配置 classpath**——只要有 Java 17 或更高版本：

```bash
java -jar probe.jar
```

预期输出（节选）：

```
[PASS] patienceLow 首次成立的 stall 次数 = 13 —— 期望=13，实际=13
[PASS] 连续无收益第 13 次真正进入 COLLAPSE —— 期望=13，实际=13
[PASS] COLLAPSE 下 needsRest/exhausted 互斥（恰好一个为真） —— true
---
结果：24 PASS / 0 FAIL
```

有任意一条 FAIL，程序以非零码退出。这是这份仓库里唯一的可执行物，
放出来的目的只有一个：让"24/0"这个数字可以被任何人复核，而不是只能信文档里的转述。

探针源码（4 个 Kotlin 逻辑类 + 1 个 Java 探针，共约 1200 行）没有随 jar 一起公开——
理由同上：这里发布的是病历证据，不是实现。jar 本身可反编译，愿意深究的人可以自己看。
